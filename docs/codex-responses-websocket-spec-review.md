## 1. 范围、方法与交付

本轮仅编写文档。交付开发 spec、本文复审记录，以及 [.gitignore](../.gitignore) 中针对这两个文件的精确白名单；没有修改运行时代码、生成绑定、数据库或真实 CLI 配置，没有暂存、提交或推送。

审查分为三个角度：

- 配置审查：独立核对 settings/DTO/SQL、表单与复制、导入导出、native/WSL 配置写入和恢复、校验命令。
- 链路审查：独立核对每条 create/每次 attempt 的处理责任、认证和插件、流门控、用量终态、恢复预算、并发与关闭。
- 主审查：通读完整 spec，合并发现，核对阶段依赖、当前事实与新增合同的区分，并检查引用与格式。

两项独立审查均为只读。初稿审查后完成修订，并对修订部分再次回读；下面记录实际发现和处置，不把新增设计描述成原有能力。

## 3. 仍需验证的事项与开发门槛

以下是主 spec 的 V01–V06，不是遗漏的产品选择，也不需要用户重新确认默认策略。开发者必须提供实验记录后才能冻结：

| 验证项             | 当前能证明什么                                                           | 尚不能证明什么 / 不通过怎么办                                                      |
| ------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| V01 自动完整重发   | 固定版本源码和测试体现 retryable error、连接 reset、后续 full input 行为 | 未跑真实 CLI + 工具 + 跨 provider 故障注入；失败则停止恢复主实现，不能用删引用替代 |
| V02 生成级关联     | session/turn 级别不足，同 turn 可有多次 create                           | 尚未确认跨 WS/HTTP 重试稳定的生成级关联；有歧义就不能放行                          |
| V03 预热           | generate=false 不等于普通生成                                            | HTTP-only 路径如何保留真实预热/后续历史语义需实验；不能伪造成功引用                |
| V04 资源与时间预算 | 已规定有限帧/队列/门控/恢复状态和初值                                    | 实际单事件、队列、空闲连接和恢复记录上限仍需测量冻结；不能宣称已验证总 RSS         |
| V05 代理/TLS       | 现有 reqwest 策略和生命周期入口可定位                                    | 新 WS 库不会自动继承这些策略；必须逐平台/代理实测，不允许绕代理或关闭 TLS 验证     |
| V06 支持范围       | 本机首个目标为 Codex 0.156.0，参考源码版本已固定                         | 不能外推所有 CLI、OAuth、WSL 组合；版本识别与未知客户端处理仍需 M0 冻结            |

这些门槛不影响本次文档交付完成，但阻止将设计稿当成已通过协议实验的实施结果。M0 使用临时测试 home 和本地 mock，不改变真实用户配置；之后仍须在生产请求链重跑相应集成用例。

## 9. 版本门禁根因修正（2026-09-27）

现场排查确认：独立 CLI 是 `0.156.0`，实际连接 AIO 的桌面端内置 CLI 是 `0.158.0-alpha.2.1`。原 [ingress](../src-tauri/src/gateway/responses_ws/ingress.rs) 将两种 `0.156.0` User-Agent 写成唯一准入条件，导致其他版本在访问供应商前收到 426 并改走 HTTP。供应商 WS 开关与反向代理设置不能修复这一处本地拒绝。

根因是将“当前测过的版本”当成“只有该版本能用”，同时将跨连接安全恢复的元数据要求扩大成普通 WS 请求的准入条件。前述 RV13/V06 的版本门控方向及 §8 的固定版本提示已撤销；当前合同以主 spec §6.1、§7.4、T36、V06 为准。

本轮修正范围：

- 普通 WS 按 Responses 协议接入，不按版本、User-Agent 或是否具备恢复元数据拒绝合法请求。同 socket 续接仍绑定实际 response ID、provider/账号及上游连接上下文；来源、接管、资源限制与协议输入校验继续生效。
- `Generation.identity: Option<RecoveryIdentity>` 仅解耦 owner/nonce；所有正式生成保留 `RequestState`、提交门控及原预算。自动恢复单独核验 owner、AIO nonce、完整历史与原子认领；错误或过期本地 nonce 不能降成新请求绕过校验。已提交输出、历史不完整或归属不明时禁止透明重放。
- 同 socket 可复用已持有的 nonce，但完整 input 仍验证已完成历史前缀；Upgrade header/body 的本地 nonce 统一检查冲突，首个正式生成后移除固定 header nonce，防止串 turn。未知历史字段可以用于首个普通请求和有效引用续接；丢弃引用后的全量重建仍须证明完整历史，不能把协议准入解释成任意重放兼容。
- UI 只说明供应商能力、HTTP 可用性及新会话生效要求，不让用户维护指定版本。真实 CLI 用例和探针显式选择实际二进制并记录版本，不再限定一个版本才能运行。
- [项目工程规范](../.agents/skills/aio-coding-hub-dev/SKILL.md) 补充约束：测试版本只作证据；基础协议与恢复资格分开；桌面内置 CLI 不能用 shell CLI 版本代替。

已保留 0.156.0 的历史测试记录。本轮全网关 932 项通过，其中 WS 66 项；桌面内置 0.158.0-alpha.2.1 与独立 0.156.0 各两个真实 AIO router 用例通过，桌面 CLI 的直接协议探针 11 场景通过。CodexTab 26 项及 lint/typecheck/Clippy/fmt 等静态检查通过。完整执行范围与仍未完成的平台验收见 [本轮实施记录](./codex-responses-websocket-m0-report.md#版本兼容性修正后的复验2026-09-27)，不沿用前轮结果冒充当前验证，也不把测试版本重新写成白名单。
