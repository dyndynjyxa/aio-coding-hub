# OAuth 账号额度预估

供应商列表的 OAuth 用量行显示 Codex / Claude 当前窗口的预估总额度与剩余额度。首页复用同一个组件。

采用 [sub2api 的 Codex 周额度预估公式和显示条件](https://github.com/Wei-Shaw/sub2api/blob/4d9ac3e482106d2da3a39fe3e546d8d6801f1cc1/frontend/src/components/account/AccountUsageCell.vue#L829-L846)：

```text
已用比例 = 100 - 上游剩余百分比
预估总额度 = 当前窗口本地已用费用 × 100 / 已用比例
预估剩余额度 = 预估总额度 × 剩余百分比 / 100
```

- 用上游重置时间减去窗口长度确定统计起点；Codex 优先采用上游 `limit_window_seconds`，缺省为 5 小时 / 7 天；Claude 为 5 小时 / 7 天。
- 费用来自该来源账号成功、未排除且没有错误码的本地请求日志，包含日志中记录为使用该来源账号的跨 CLI 桥接请求；不根据当前桥接配置回溯归属。使用日志记录的 USD 费用口径（含请求当时的供应商费用倍率）。不查询或修改订阅余额，也不新增上游调用。
- 与 sub2api 一样，只要当前窗口已记录的费用和上游已用比例是有效正数，就继续计算并显示预估金额；部分请求缺少费用不会阻止整个窗口估算。悬停提示会说明缺失费用的请求数，以及估值可能偏低。每次刷新按当前累计费用和上游用量重新计算，不保留上次估值作为回退。
- 没有费用样本、费用总额为零或已用比例为零时显示“待积累用量”；全部请求均缺少费用时显示“费用数据不足”；重置后显示“已重置，待刷新”，不会沿用旧窗口金额。
- 估算查询失败时保留正常的 OAuth 用量刷新和配额保护行为。

金额带 `~`，仅供参考，不代表上游承诺的美元余额。通过其他客户端使用账号、切换账号或改变模型/费用倍率，会影响估算准确性。已有点数、重置次数及配额路由保护继续使用原有真实数据。
